## 1. Threat model

**Assets**

1. **`K_main`'s SOL float** spent on openings: ≈ 0.0226 SOL a collection (`unlock::OPEN_COST`: the wX mint's rent, its metadata's rent and the 0.01 SOL Metaplex fee, the DBC config's rent, fees), above the 0.05 SOL `RESERVE_LAMPORTS` the money flows keep. The ceremony funds ≈ 0.2 SOL (§3: about eight openings); fees refill it only from coins on collections already open.
2. **The order of openings** (operator decision 2026-10-12, "the people choose"): the FIFO `CoinsState.requested`, at `OPENS_PER_DAY` = 8, and **the availability of opening itself**: a collection that cannot open cannot have a coin.
3. **The runner's authority** to hand the canister evidence: `frog_floor_reading(coll, …)`, `frog_proof(coll, …)`, `frog_offer(_protected)(coll, …)`, `sol_nft_evidence(coll, …)`, `relay_quote`, `eth_floor_evidence`. The canister judges each on its own reads; the runner is the operator identity.
4. **Cycles**: every ingress update the canister accepts, every outcall the opening pass makes.

**Actors**

| Actor | Capability | In scope |
|---|---|---|
| An anonymous spammer | `coins_request_open(index)` as often as they like (anonymous, accepted by `inspect_message`); any query | yes |
| A griefer on Solana | Transfers lamports to any address (no signature of the recipient), reads every public key and transaction, front-runs | yes |
| A hostile marketplace or price API (Magic Eden, CoinGecko, Ordinals Wallet, UniSat, OpenSea) | Any response body, status and timing to the runner's requests | yes |
| A compromised runner | The operator identity's calls (every operator method, not only the runner's) | noted: it is the operator (§8 of the ceremony) |
| The operator | `coins_pin`, `coins_set_auto_open`, `coins_set_off`, the launch files, the runner's environment | trusted, foot-guns checked |
| A visitor of the site | The "Open it" button, any number of tabs | yes |

### C4-01: A tiny transfer to a derived address refuses a collection for good (High)

**Files:**
- `src/coins/open.rs:29-37` (`mint_seed`, `wx_mint_of`: `createWithSeed(K_main, "wx:<i>", Token)`)
- `src/coins/open.rs:233-247` (`pass`: an account at the mint address that does not decode as a Token mint is `refuse(e)`)
- `src/coins/open.rs:257-267` (the same for the config at `KeyPath::Config(i)`: `DbcConfig::decode` fails on a System owner, `refuse(e)`)
- `src/coins/open.rs:56` (`mint_tx`: `create_with_seed`, which Solana refuses on an address holding lamports)
- `src/coins/open.rs:118-131` (`register`: the index and the symbol of a refused pin stay taken); no method clears `ColStage::Refused` or removes a pin
- `src/coins/open.rs:173-181` (`request_open`: a refused collection is refused)

**Description.** Every pin `launch_pins` writes has `wx_mint: None, config: None`: the canister makes both, at addresses anyone can compute. The wX mint is `createWithSeed(K_main, "wx:<i>", Token)`; `K_main` is public (`sol_address`, the fee payer of every transaction). The config is `KeyPath::Config(i)`, a threshold-Ed25519 derivation from the canister's public key, reproducible by anyone (A4-02 made the same observation for the nonce account). A plain System transfer of the 0-byte rent-exempt minimum (890,880 lamports) to either address leaves a System-owned, data-less account there. The opening pass reads the address, the decoder refuses the owner, and `refuse` sets `ColStage::Refused` for good. From then on `coins_request_open` refuses the collection ("the operator must look at it"), but the operator has no method to clear a refusal or remove a pin, and `register` refuses the same index and the same symbol. A re-pin under a new index and a new symbol is as predictable (the attacker pre-funds the next indices too: 1,000 of them cost ≈ 0.9 SOL). Even without the canister's read, Solana's `CreateAccountWithSeed` fails `AccountAlreadyInUse` on such an address, so the mint could not be made there.

**Scenario.** Before (or right after) the ceremony, an anonymous attacker sends 890,880 lamports to `wx_mint_of(K_main, i)` for i in 0..24: ≈ 0.021 SOL. The first request for each collection refuses it; every collection on the site shows "Not available … The operator has to look at it"; no coin can be launched anywhere. The costly variant: the attacker watches for a collection's mint transaction (public) and pre-funds its config address; the pass refuses the collection after `K_main` paid the mint, the metadata and the Metaplex fee (≈ 0.0166 SOL of the 0.0226).

**Impact.** Every collection's opening, hence every coin launch, closed by anyone for ≈ 0.02 SOL, anonymously, permanently: recovery needs a code change and a timelocked upgrade, and re-pinning (new index, new symbol) breaks the site's and runner's symbol keys (C4-12). Funds are not taken (the variant burns float). Rated High: product-wide denial at negligible cost with no operator escape.

**PoC.** `tests/audit_c4_opening.rs`:
- `poc_c4_01_a_tiny_transfer_to_the_derived_wx_mint_address_refuses_the_collection_for_good`: two pinned collections, `RENT0` planted at each derived mint address: both requested, both `Refused` ("SPL mint …"), nothing signed, `K_main` untouched; the request is refused after, the pin cannot be re-made under its index or its symbol, and a fresh index under a fresh symbol, pre-funded the same way, is refused too.
- `poc_c4_01_a_prefunded_config_address_refuses_the_collection_after_the_float_paid_its_mint`: the mint step signs and lands, then `RENT0` at `KeyPath::Config(0)`: the collection is `Refused` ("DBC PoolConfig …") after `K_main` paid the mint's rent.

**Fix.** Treat a System-owned, data-less account at a derived address as "not made yet" and make the account over it: for the mint, `Transfer` (top up to the rent) + `AllocateWithSeed` + `AssignWithSeed` + `InitializeMint2` (an outsider can transfer to a seed address but never allocate or assign it: A4-02's fix); for the config, DBC's `init` already takes a pre-funded account, so only the read must stop refusing (go to `step_open_config`). Keep refusing a mint or config owned by another program or with the wrong contents. Give the operator a way out of `Refused` (re-check, or unpin a never-opened pin and free its symbol). The fix must make both PoCs' `Refused` assertions fail and the collections open. The test chain should refuse `CreateAccountWithSeed` on an address holding lamports, as Solana does (C4-13).

**Fixed (2026-10-12):** a System-owned, data-less account at a DERIVED address (`open::squatted`; a pinned address is still only read) is "not made yet": the mint is made over it in place (`mint_tx(…, held)`: `AllocateWithSeed(82, Token)` signed by `K_main` as the base, a top-up `Transfer` to the rent when it holds less, then `InitializeMint2` and the metadata; `CreateAccountWithSeed` only when the address holds nothing), and the config step is signed over a pre-funded config address (DBC's `create_config` is an Anchor `init`, which tops up, allocates and assigns). Anything else at either address (another owner, data) is still refused. The operator's way out of `Refused`: `coins_retry(index)` (operator, not while paused; `open::retry_refused`) pins the collection again under its own index and symbol, clears its steps' waits and queues it; the pass re-reads the chain. Regression: `fixed_c4_01_a_tiny_transfer_to_the_derived_wx_mint_address_no_longer_refuses_the_collection` and `fixed_c4_01_a_prefunded_config_address_is_made_over_not_refused` (the PoCs inverted: the collections open, against the C4-13 harness that refuses `CreateAccountWithSeed` on a funded address), `fixed_c4_01_the_operator_retries_a_refused_collection_under_its_own_index` (`tests/audit_c4_opening.rs`).

### C4-02: One caller queues every pinned collection (Medium)

**Files:** `src/coins/api.rs:149-153` (`coins_request_open`: no caller, no limit, no cost); `src/coins/open.rs:156-195` (`next_pinned`, `request_open`: FIFO by arrival); `src/coins/state.rs` (`OPENS_PER_DAY` = 8); `src/canister.rs:286-289` (`may_ingress` admits it anonymously).

**Description.** The queue records `(index, asked_at)` and nothing about who asked. Anyone can request every pinned collection (24 at the ceremony, 27 with C4-03, 41 later) in any order with 24 free calls. The canister then opens them in that order at 8 a day, ≈ 0.0226 SOL each, until the float reaches the reserve (the ceremony's ≈ 0.2 SOL: about six openings above the 0.05 reserve), and then waits for fees, which only coins on opened collections bring. A creator who asks after the spammer is told "after 23 other request(s)".

**Impact.** "The people choose" becomes "the first script chooses": the opening order, the float (up to 24 × 0.0226 ≈ 0.54 SOL spent on collections nobody launched on, the Metaplex fee and rent locked in accounts the canister cannot close), and days of delay for the real creator; with the float spent, the delay lasts until the operator tops it up. Bounded by the pins (each collection opens once), no theft: Medium, as B1-05 was for the desk.

**PoC.** `poc_c4_02_one_caller_queues_every_pinned_collection_and_the_creator_waits_behind_them`: 24 pins, 23 requests in reverse order, the creator's request answers "after 23 other request(s)", and the spammer's first pick opens first.

**Fix.** Make a request cost something or count per caller: refuse the anonymous principal and limit each principal (and all callers) per hour, as `open_intent` does; or let a request jump the queue only when tied to a launch (the creator's signed DBC pool transaction or a small SOL deposit to `K_main`, refunded at the first coin); or open at most one requested collection per day above the reserve that has no coin yet. Report the queue position against the opening pace in the answer.

**Fixed (2026-10-12):** the rule (`open::check_request`): the queue holds at most `MAX_QUEUED` = 8 pending requests (a day of openings at `OPENS_PER_DAY`); at most `REQUESTS_PER_HOUR` = 4 are accepted an hour from all callers together, of which at most `ANON_REQUESTS_PER_HOUR` = 2 from the anonymous principal (the site's visitors are all one caller); a named principal holds one pending request at a time and at most `CALLER_REQUESTS_PER_HOUR` = 2 an hour. Why: principals cost nothing, so per-principal limits alone stop nothing; the overall hourly and queue bounds are what a script cannot get around, and they keep the worst wait a real creator meets to a day of openings (the queue is never longer than the pace drains in a day) while the anonymous site still works (2 an hour is far above the 8-a-day pace). A deposit or a signed launch transaction would price the spam out entirely, but would make the site's free "Open it" a wallet flow; the float burn stays bounded by the pins and `OPENS_PER_DAY` as before. `coins_request_open` passes the caller's principal (`msg_caller`); the answer gives the position against the pace ("after N other request(s): at most 8 open a day, as the float allows"). Regression: `fixed_c4_02_one_caller_no_longer_queues_every_pinned_collection` (the PoC inverted: anonymous stops at 2, a named caller at one pending, fresh principals at 4 an hour, the queue at 8).

### C4-03: The ceremony pins the Robinhood Chain collections, and opening is not gated on a pipeline (Medium)

**Files:** `examples/launch_pins.rs:155` (`main` merges `robinhood-collections.json` into `nft-pilot.json`'s collections), `:94-137` (`select` pins every 4663 entry, whatever `--count`), `:258-263` (`the_default_is_the_24` loads `nft-pilot.json` only); `src/coins/unlock.rs:28-30` ("Pinned after the ceremony, once the 4663 `evm_chains` entry … is read back"); `docs/v9/ceremony-canister-only.md` §2 ("for the 24", "None is in the files today"); `src/coins/open.rs:173-195`, `:206-283` (`request_open` and `pass` check only that the index is pinned).

**Description.** Run as the runbook writes it (`--count 24`), the example writes 27 pins: `00`–`23` and `38-stonkbrokers`, `39-chainmancers`, `40-rekttradooors` (`EthNft { chain_id: 4663 }`), and prints "27 pins written … 0.610 SOL were all 27 to open" (run on `79b4e60` for this audit). The handoff and `unlock.rs` say the Robinhood collections are pinned after the ceremony, once the 4663 `evm_chains` entry and `eth_nft.collections` are in; an operator who pins every `.args` file of the directory pins them at the ceremony. The canister then opens any pinned collection on the first anonymous request: nothing checks that a 4663 listing has its `evm_chains` entry and its `eth_nft` collection, that an Inscriptions listing is live (Bitcoin Frogs is dormant on a fresh install until `frog_wake(4)`; the other Ordinals with `--include-ordinals`), or that a Solana collection's feed is configured.

**Impact.** A collection whose wX cannot be minted (no floor evidence, no buy, no deposit path on its chain) is opened from the float and shown Open on the board; creators can launch coins on a curve whose quote token nobody can obtain. Float ≈ 0.068 SOL for the three; the confusion is the larger cost. Medium: the operator's foot-gun is built into the documented command, and the canister has no readiness gate behind it.

**Fix.** In `launch_pins`, pin the 4663 entries only with an explicit `--include-robinhood` (as `--include-ordinals`), and test the default against the merged files. In the canister, refuse `request_open` (and skip in `pass`) for a pin whose pipeline is not ready: an `EthNft` listing whose chain has no `evm_chains` entry or whose collection is not in `eth_nft.collections`, an `Inscriptions` listing that is dormant, a `SolNft` collection the Solana NFT flow does not know. Fix the runbook's §2.

**Fixed (2026-10-12):** the operator decided "no picking": the default pins are every collection with a pipeline, `LAUNCH_COUNT` = 38 (the 11 Ethereum, Bitcoin Frogs, the 12 Solana, the 14 Ordinals, live by default); `launch_pins` never writes a Robinhood Chain pin by default (`select` skips `ORDER`'s `Source::Robinhood` entries and every `chainId` 4663 entry; `--count` above 38 is refused) and pins the three only with `--include-robinhood`, after the 4663 read-back; `--include-ordinals` is accepted as a no-op with a note. In the canister, `open::pipeline_ready`: an `EthNft` listing on a chain other than Ethereum opens only once that chain is in `evm_chains` (`canister::evm_chain_ids`); a request for one is refused "cannot open yet", and the pass (auto-open included) passes over it. An Inscriptions listing needs nothing more (live by default); a SolNft one is the Solana NFT flow's. The runbook's §2 is rewritten. Run of the example on the fix: "38 pins written … 0.858 SOL were all 38 to open". Regression: `fixed_c4_03_a_robinhood_pin_opens_only_once_its_chain_is_installed` (`tests/audit_c4_opening.rs`); `the_default_is_the_38_and_never_a_robinhood_collection`, `include_robinhood_adds_the_three_at_their_order_indices`, `a_4663_collection_is_pinned_after_the_order` (`examples/launch_pins.rs`, on the merged launch files); `the_order_is_the_designs`, `the_ceremony_pins_every_collection_with_a_pipeline_and_each_has_what_its_pin_needs` (38, the Ordinals included).

### C4-04: A waiting head holds every later request (Low)

**Files:** `src/coins/open.rs:156-170` (`next_pinned` always returns the oldest openable request), `:233-238` (a pinned mint the chain lacks: `Waits` for ever), `:302-326` (`step_open_mint`'s refusal waits 6 h, `:350-383`: only a config step ever becomes `Refused`), `src/coins/run.rs:77-82` (a `Waits` pass comes back every `OPEN_EVERY` = 120 s).

**Description.** The pass serves the head of the queue or nothing. A head that waits for a reason other than the float (a `wx_mint` or `config` the operator pinned and the chain does not hold; a mint step the simulation keeps refusing, which is retried every 6 h and never refused; keys or reads failing) holds every request behind it, and the pass re-derives keys and re-reads three accounts every two minutes meanwhile. No attacker can create these states without the operator (C4-01 refuses rather than stalls), so this is an operator foot-gun with a queue-wide effect.

**PoC.** `poc_c4_04_a_waiting_head_holds_every_later_request`: collection 1 pinned with a mint the chain lacks, collection 2 ready; both requested; after an hour of passes nothing is signed and the queue is still `[1, 2]`.

**Fix.** When the head waits for a reason that is the collection's own, move on to the next openable request (keep the head's place); refuse a mint step after N simulation refusals as B3-10 does for the config; back the waiting head's re-reads off.

**Fixed (2026-10-12):** the pass records what it waits on per requested collection (`CoinsState.stalls`: since, last look, why, and whether the wait is the collection's own: a pinned mint or config the chain lacks, the metadata missing, a step refused by simulation or waiting its retry; the float, the pace, the keys and the reads are everyone's and never skipped). A request waiting on its own reason for `HEAD_PATIENCE` (30 min) is passed over for the next openable request; it keeps its place and is looked at again every `STALLED_LOOK_EVERY` (1 h), which also backs its re-reads off. `coins_open_queue` shows it as `skipped` with the reason. Regression: `fixed_c4_04_a_waiting_head_no_longer_holds_every_later_request` (the PoC inverted: collection 2 starts after the head's patience, within the hour; 1 keeps the head).

### C4-05: `coins_request_open` is free and unlimited, no-ops included (Low)

**Files:** `src/canister.rs:270-289` (`inspect_message` accepts every `coins_request_open`), `src/coins/api.rs:149-158`.

**Description.** The method is the canister's second anonymous update. Every accepted ingress message is charged to the canister (reception and execution), including the calls that change nothing: an index that is not pinned, open, refused or already requested. There is no per-caller count (`open_intent` has one). `inspect_message` may read state, so it could refuse every call that cannot change the queue at no cost to the canister.

**Impact.** A cycles drain at the rate an attacker can push ingress through the boundary nodes; the same exposure as `open_intent`, without its counters. Bounded by the subnet's ingress limits; no state grows (the queue is bounded by the pins).

**Fix.** In `inspect_message`, accept `coins_request_open` only when its argument is a pinned index that is neither open, refused nor already requested (decode the `nat32`); refuse the anonymous principal if C4-02's fix counts per principal.

**Fixed (2026-10-12):** `inspect_message` decodes a stranger's `coins_request_open` argument (`coins::api::may_request`) and accepts it only when `open::check_request` answers `Ask::New`: not paused, a home, the module on, pinned, not open, not refused, ready (C4-03), not requested already, within C4-02's limits. The operator and controllers are admitted as before. Regression: `fixed_c4_05_only_a_request_that_would_queue_is_accepted_as_ingress` (`tests/audit_c4_opening.rs`); `only_the_operator_and_controllers_are_admitted_and_strangers_only_to_an_open_board` (`canister.rs`).

### C4-06: The runner's step problems are sticky (Low)

**Files:** `ops/src/inscriptions.ts:139-145` (`bitcoinStepsOnce`: `problems.add(why)` for an unpaired entry, never removed), `:114-117` (`frogProofOnce`: the same for a members file), `:66-81` (`ListingMembers` keeps an error for the process); `ops/src/runner.ts:420-425` (`/healthz` reads `inscProblems`).

**Description.** An entry of `RUNNER_INSCRIPTIONS` that does not pair with a canister collection at one pass (the operator configured the runner before pinning the collection, or one read came back short) adds its problem to the set `/healthz` reports, and nothing removes it when the entry pairs: the runner keeps answering 503 while it works, until it restarts. A members file fixed on disk is not reloaded either.

**PoC.** `ops/test/audit_c4_runner.test.ts`, "C4-06 …": unpaired, then paired and served, the problem still in the set.

**Fix.** Recompute the set each pass (clear the entries' and the proof step's problems before the pass, add what still holds); retry a failed members load after a while.

**Fixed (2026-10-12):** `bitcoinStepsOnce` and `frogProofOnce` own their problem keys: each pass clears the ones it added last time and adds back only what still holds (other keys of the /healthz set untouched); `ListingMembers` retries a members file that failed to load or did not match its root after `MEMBERS_RETRY_S` (300 s). Regression: "fixed C4-06 …" (two tests: unpaired then paired, and a members file fixed then reloaded) in `ops/test/audit_c4_runner.test.ts`.
